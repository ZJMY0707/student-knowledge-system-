# 数据库设计文档 - 学生知识库与日程标注系统

## 1. ER图

![ER图](./er_diagram.png)
> 实际绘制可使用 Draw.io / PDMan，导出图片放于此。  
> **核心关系说明**：
> - 用户 (`t_user`) 1 : N 知识条目 (`t_knowledge_entry`)
> - 用户 1 : N 分类 (`t_category`)
> - 用户 1 : N 标签 (`t_tag`)
> - 用户 1 : N 日程任务 (`t_task`)
> - 分类 1 : N 知识条目
> - 知识条目 N : M 标签 (通过 `t_entry_tag`)

## 2. 表结构汇总

| 表名 | 说明 | 关键字段 | 关联关系 |
|------|------|----------|----------|
| `t_user` | 用户账户 | id, username, password | 主表 |
| `t_category` | 知识分类 | id, user_id, name, parent_id | 用户一对多；自关联支持父子分类 |
| `t_knowledge_entry` | 知识条目 | id, user_id, category_id, title, content | 属于一个用户和一个分类 |
| `t_tag` | 标签 | id, user_id, name | 用户一对多 |
| `t_entry_tag` | 条目-标签中间表 | entry_id, tag_id | 多对多关联 |
| `t_task` | 日程任务 | id, user_id, title, deadline, status | 用户一对多，轻量级 |

## 3. 字段命名规范

- 表名：`t_` 前缀 + 下划线小写命名 (e.g., `t_knowledge_entry`)
- 主键：统一 `id` (BIGINT AUTO_INCREMENT)
- 外键：`关联表名_id` (e.g., `category_id`)
- 审计字段：`create_time`, `update_time` (DATETIME，自动维护)
- 状态字段：使用 `VARCHAR` 枚举值 (e.g., `status` 列)

## 4. 约束与索引

- **唯一约束**：
    - `t_user.username`
    - `t_tag (user_id, name)`
- **外键约束**：均设置 `ON DELETE CASCADE` 或 `RESTRICT`，保证数据完整性。
- **普通索引**：
    - `t_knowledge_entry (user_id, category_id)`
    - `t_knowledge_entry (title)`
    - `t_task (user_id, deadline)`

## 5. 演示数据说明

- 3个用户（2普通+1管理员），密码占位符（实际使用BCrypt）。
- 分类支持二级（设计模式下的JVM底层）。
- 知识条目与标签关联示例覆盖多对多场景。
- 日程任务包含不同优先级和状态。

## 6. 后续扩展建议

- 可为知识条目增加 `attachment_url`（附件）和 `favorite`（收藏）字段。
- 日程表可增加 `repeat_rule` 支持重复任务。
- 若笔记需全文搜索，可接入 Elasticsearch 或 MySQL 全文索引。
