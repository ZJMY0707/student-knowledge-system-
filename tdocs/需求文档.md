一、项目概述
项目名称：学生个人知识库与日程标注系统
目标用户：在校学生（普通用户）、系统管理员
核心价值：帮助用户管理学习笔记/资料（知识库）并规划学习日程
业务范围：知识条目的增删改查、日程计划的创建与状态跟踪、基础数据统计


二、功能性需求
1. 用户与权限管理（5分）
   支持注册/登录（学号/邮箱+密码）
   两个角色：
   普通学生：管理自己的知识库和日程
   管理员：查看所有用户、重置密码、删除违规数据
   权限控制：不同角色登录后看到不同菜单

2. 前端交互主框架（5分）
   左侧菜单栏（二级导航），例如：
   知识库管理 → 我的笔记 / 笔记分类
   日程管理 → 我的日程 / 已完成任务
   数据统计 → 学习分析 / 系统概况
   顶部区域：系统Logo、当前用户、退出
   底部：版权说明、团队信息
   主内容区支持不同功能模块的切换

3. 基本信息维护（20分）——至少4个模块
   知识条目管理：增删改查笔记（标题、内容、标签、创建时间）
   分类管理：增删改查知识分类（如“Java”“数学”）
   标签管理：增删改查标签（用于知识库检索）
   日程任务管理：增删改查学习任务（标题、截止时间、优先级）

4. 复杂业务流程（15分）
   多表关系：知识条目用文件树 + 标签的混合元数据模型管理
   状态管理：日程任务有状态（待开始 / 进行中 / 已完成 / 逾期）

5. 数据统计与可视化（10分）
   知识库统计：各分类下笔记数量（饼图/柱状图）
   系统监控：总用户数、总笔记数


三、非功能性需求（对应质量要求20分）
用户体验：界面布局清晰、按钮反馈明确、表单输入提示、加载等待提示

程序质量：
输入校验：必填项、日期格式、长度限制
异常处理：网络错误提示、操作成功/失败弹窗
会话管理：登录超时自动跳转、Token过期处理
部署运行：前端打包为.jar、后端打包为.jar、提供启动脚本


四、数据需求（对应文档中的数据设计10分）
需要规划清楚：
表命名：t_user、t_knowledge_entry、t_category、t_task、t_tag等
字段规范：主键（id）、外键约束、非空、唯一索引、默认值
关系：一对多、多对多清晰，使用中间表
示例数据：准备3～5条演示数据用于展示
